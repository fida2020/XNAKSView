# XNAKView Mobile

Flutter app for XNAKView — a single codebase targeting **both Android and iOS**.
There is no platform-specific product logic in this app; `android/` and `ios/`
exist only as the platform embedding shells Flutter requires, generated by
`flutter create` and kept under standard configuration.

## Platform targets

| Platform | Identifier                  | Status (Step 1)                         |
|----------|------------------------------|------------------------------------------|
| Android  | `com.balochsahab.xnakview`   | Configured, builds via Gradle (Kotlin)   |
| iOS      | `com.balochsahab.xnakview`   | Configured, builds via Xcode (Swift)     |

Both platforms share the exact same `lib/` source. Nothing in `lib/` imports
`dart:io` platform checks to branch product behavior — if platform-specific
behavior becomes necessary later (e.g. push notification registration, native
payment SDKs, camera/mic permissions for LIVE), it belongs behind an
abstraction in `core/` (see `core/storage/secure_storage.dart` for the pattern
already used) with a single implementation per platform, never scattered
`Platform.isAndroid` / `Platform.isIOS` checks in feature code.

Web/Windows/Linux/macOS folders were generated by the Flutter tool by default
and are not a target for this product at this stage; they are harmless to
leave in place and are not built or tested.

## Architecture

```
lib/
├── app/            # App widget: theme + router wiring
├── core/
│   ├── config/      # Compile-time environment config (--dart-define)
│   ├── errors/       # Shared AppException hierarchy
│   ├── network/       # ApiClient abstraction (Dio-backed)
│   ├── router/         # go_router setup, auth-aware redirects
│   ├── storage/         # SecureStorage abstraction (flutter_secure_storage-backed)
│   ├── theme/            # AppTheme (light/dark)
│   └── widgets/            # Shared widgets (e.g. AppErrorWidget)
└── features/
    ├── auth/         # Auth state/controller + placeholder screens (full flows: Phase 2)
    └── splash/       # Startup screen
```

State management: **Riverpod**. Routing: **go_router** with redirect logic
driven by `authControllerProvider`. Networking: **Dio**, wrapped behind
`ApiClient` so feature code never depends on Dio directly. Secrets/tokens:
**flutter_secure_storage**, wrapped behind `SecureStorage`.

## Running locally

```bash
flutter pub get
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000/api/v1   # Android emulator -> host backend
flutter run --dart-define=API_BASE_URL=http://localhost:4000/api/v1  # iOS simulator -> host backend
```

## Verifying platform configuration

```bash
flutter doctor            # confirms Android/iOS toolchains are installed
flutter analyze           # static analysis (must be clean)
flutter test               # widget tests
flutter build apk --debug   # Android build (requires Android SDK)
flutter build ios --no-codesign --debug  # iOS build (requires Xcode, macOS only)
```

`flutter build ios` can only run on macOS with Xcode installed — it cannot be
verified from a Windows development machine. Android builds can be verified
on Windows as long as the Android SDK/toolchain is installed.

## What's deliberately not built yet

Full authentication UI, video feed, LIVE, dating/matching, chat/calls,
coins/gifts, and any monetization or AI features — per the project roadmap
(see `../docs/ROADMAP.md`), these are later phases. Step 1 only establishes
the foundation both platforms build on top of.
